# Fleet v0.1.4 onboarding and image handoff decision

## Verdict

Fleet's enforced contract was operational in v0.1.3, but first-use contract construction and image
handoff still depended on undocumented operator knowledge. v0.1.4 turns both into maintained behavior.

## Decisions

- `fleet.mjs init --list --json` exposes the maintained template gallery.
- `research`, `implementation`, `verification`, and `image-generation` emit schema-valid contracts.
- Writer and image templates require a visible user confirmation reference before they are emitted.
- The exact verifier machine role is `independent-verifier`; `verifier` remains prose only.
- A generated image's path is not visual evidence. Parent Claude opens the workspace artifact with its
  Read tool and performs visual QA before presentation. Consequential visuals also receive a fresh
  visual verifier lane.

## Live evidence and reusable lesson

On Windows with Codex CLI 0.147.0, a confirmed Fleet image lane used the built-in `$imagegen` route and
produced a non-empty 1254 x 1254 PNG. The first cleanup attempt raced the still-closing supervisor and
left the temporary directory locked; a later owned cleanup succeeded. Live artifact smokes must wait
for owned supervisor shutdown before recursive workspace cleanup. A generated file proves capability;
successful cleanup remains a separate assertion.
