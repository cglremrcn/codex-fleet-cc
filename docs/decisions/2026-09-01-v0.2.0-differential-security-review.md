## What Changed

The release repairs four trust boundaries: structured worker results, durable supervisor admission,
Codex app-server authority propagation, and installed runtime ownership. It also adds truthful
interruption recovery, bounded status/result views, scalable terminal navigation, and version-parity
release automation.

| Surface | Risk | Security effect |
|---|---|---|
| Result parsing and persistence | High | Keeps strict allowlists, bounds evidence, rejects traversal, and verifies commit claims independently. |
| Supervisor timeout and recovery | High | Distinguishes sent/unknown requests and prevents blind mutable redispatch. |
| Runtime sandbox/network policy | High | Maps admitted authority explicitly on start, resume, and continuation. |
| Process ownership | High | Retains exact PID/start-identity checks before termination. |
| Status and TUI | Low | Read-only observation, bounded rendering, and terminal restoration. |
| Packaging and installation | Medium | Version parity, deterministic archive, exact confirmation, and owned rollback remain enforced. |

The commit timeline is linear: protocol normalization and persistence first, recovery and timeout
handling second, runtime authority third, operator surfaces fourth, and release/install verification
last.

## Critical Findings

No open critical, high, or medium security findings were confirmed.

### Resolved low finding: Windows Codex wrapper path compatibility

**File:** `scripts/run-live-smoke.mjs:51`  
**Commit:** `c544ef362bf91bf79396a8322fbafc13bf1be26d`  
**Blast radius:** Three diagnostic call sites; low.  
**Test coverage:** Yes, including a path containing spaces.

The first diagnostic implementation constructed one `cmd.exe /c` string. Metacharacters were
rejected, so no command-injection path was demonstrated, but an otherwise valid Codex wrapper under
a directory containing spaces could not launch. A live probe against `C:\Program Files\nodejs\npm.cmd`
showed that separate `cmd.exe /d /s /c call <wrapper> <args...>` argv elements preserve the path.
The implementation now uses that form and still restricts diagnostic arguments to safe literals.

**Attacker model:** A local user able to control the diagnostic process PATH. Such a user already has
local execution ability; the realistic impact was diagnostic denial, not privilege escalation.

**Concrete failure scenario:** Install the npm/Codex wrapper under a path containing spaces, run the
live smoke, and observe the old concatenated command stop before account access. The fixed invocation
launches the exact resolved wrapper and reports `codex-cli 0.151.0`.

### Resolved low finding: failed app-server initialization retained its child process

**File:** `plugins/fleet/scripts/app-server-broker.mjs`
**Blast radius:** Every broker initialization failure; low confidentiality/integrity impact, medium
availability impact under repeated retries.
**Test coverage:** Yes, with a deterministic zero-timeout initialization and exact PID exit check.

The broker previously cleaned up when process-ownership capture failed, but not when the subsequent
app-server `initialize` request failed or timed out. Under a loaded CI run, the rejected broker left
its child process and test worker open indefinitely. Initialization is now transactional: any failure
closes the exact owned broker before the original error is returned; a cleanup refusal is surfaced as
an aggregate error rather than hidden. The spawn-heavy full suite also runs one test file at a time;
tests within each file retain their intended lane-level concurrency without overlapping independent
process-ownership fixtures.

**Wrong hypothesis retained:** The first cross-platform failures looked like a Node 22/macOS-specific
test problem. Exact Node 22.23.1 passed the file in isolation, while cancelled full-suite logs showed
the worker stopped before the runtime-adapter results and retained a child `node` process. That
observation refuted the platform hypothesis and identified the missing initialization cleanup.
Repeated matrix runs then showed random long-running Node 22 workers on different platforms, and a
two-file bound still let concurrent Windows PowerShell identity probes exceed their 15-second bound.
The file runner was therefore serialized to address shared child-process pressure rather than adding
platform exceptions or weakening the production observer timeout.

### Resolved low finding: asynchronous fixture cleanup could strand a test child

**Files:** `tests/fixtures/fake-codex-app-server.mjs`, `tests/runtime-adapter.test.mjs`

**Blast radius:** Test reliability only; no production runtime path.

**Test coverage:** The complete 26-case runtime-adapter suite and the 319-case release gate.

An ephemeral-lane test ended immediately after the app-server accepted `turn/start`. The fixture had
registered temporary-directory removal before the runtime registered broker shutdown, so Node ran
the hooks in the unsafe order. On slower Node 22 runners the fake child was still writing state;
directory removal failed with `ENOTEMPTY`, the later close hook never ran, and the worker retained the
child indefinitely. Fixture teardown now closes every registered runtime first, removes its temporary
root second, and reports all close/removal failures with `AggregateError` instead of masking either.

**Wrong hypothesis retained:** After broker initialization cleanup and file-level serialization were
fixed, the remaining random Node 22 jobs looked like leaked event-loop handles. Cancelling a duplicate
matrix run exposed the actual `ENOTEMPTY` hook failure at the ephemeral-lane test and the retained fake
Codex PIDs. That evidence refuted the generic handle hypothesis and identified deterministic teardown
ordering as the remaining fault class.

## Recommendations

### Immediate

- No code blocker remains from this review.
- Run the full GitHub PR matrix before merge; do not bypass checks.

### Before production

- Require the tag workflow and package job to pass.
- Verify the published ZIP against its checksum and provenance, then compare normalized archive
  contents to the tagged `plugins/fleet` tree.
- Refresh the Claude marketplace and installed cache only after remote `main` contains v0.2.0.

### Residual limitations

- Linux and macOS behavior was not executed locally; it is delegated to the required CI matrix.
- Playwright/browser-profile concurrency remains an external Claude/connector limitation.
- The command-exec probe proves sandboxed exact argv, not general unsandboxed build authority.

## Analysis Methodology

**Strategy:** Focused review for a medium codebase (107 JavaScript/TypeScript-family files; 59 files
changed).

The review compared the baseline and head, inspected all changed-file statistics and commit history,
deep-read the high-risk protocol/state/authority/persistence/shell diffs, traced direct production
references, mapped changed behavior to tests, searched removed validations and security history, and
ran adversarial scenarios for timeout replay, shell injection, path traversal, secret persistence,
authority widening, PID reuse, and duplicate admission.

**Confidence:** High for the Windows and protocol paths exercised locally; medium-high overall until
the cross-platform GitHub matrix and published artifacts pass.

## Appendix: Reviewed invariants

- Role names never grant authority; only the admitted authority object does.
- Mutable acceptance ambiguity never causes blind retry.
- A lane cannot verify its own result, and reported Git commits are checked in the admitted workspace.
- Persisted state excludes raw prompts, reasoning, command output, credentials, and arbitrary errors.
- State, runtime, and launcher paths remain owned, absolute, and protected against traversal/symlinks.
- Process termination requires the exact recorded process identity.
- Setup/uninstall and external mutations retain exact confirmation semantics.
